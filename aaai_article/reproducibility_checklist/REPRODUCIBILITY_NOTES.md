### 🔴 4.7 — Вычислительная инфраструктура (сейчас «no» → легко сделать «yes»)
В статье **нигде** не указаны GPU/CPU, память, ОС, версии PyTorch/CUDA.
Плюс `code/requirements.txt` **пустой** — это отдельный блокер для code appendix.

**Как исправить (30 минут):**
1. Добавить в раздел Experiments (или в аппендикс) абзац вида: «Все эксперименты
   проведены на \<GPU, напр. NVIDIA A100 80GB / RTX 3090\>, \<RAM\>, ОС \<Ubuntu
   XX.04\>, Python 3.9, PyTorch \<версия\>, CUDA \<версия\>.» (в коде видно, что
   среда — Python 3.9, по `__pycache__/*.cpython-39.pyc`).
2. Заполнить `code/requirements.txt` реальными закреплёнными версиями:
   `pip freeze | grep -Ei 'torch|numpy|torchvision|matplotlib' > requirements.txt`.
   Сейчас файл пустой — воспроизвести окружение невозможно.

После этого 4.7 → **yes**.

### 🔴 3.4 — Цитата на CIFAR-10 (сейчас «no» → тривиально «yes»)
В `references.bib` есть только MNIST (`lecun2010mnist`), а основной датасет

### 🔴 4.6 — Фиксация seed (сейчас «partial» → легко «yes»)
В коде seed фиксируется корректно (`main.py`, `federated_main.py`:
`seed_everything` → numpy/random/torch/cuda, флаг `--seed` по умолчанию 0). Но в
**тексте статьи это не описано** — отсюда «partial».

**Как исправить (10 минут):** одна фраза в Experiments: «Во всех экспериментах
seed фиксируется через `seed_everything(seed)` (numpy, random, torch,
torch.cuda), значение по умолчанию 0.» После этого 4.6 → **yes**.

**Мелкий баг в коде (стоит поправить):** `federated_main.py:99` выставляет
`torch.backends.cudnn.deterministic = True`, а `main.py` (централизованный
сценарий) — **нет**. Из-за этого централизованные прогоны могут быть не
полностью детерминированными между запусками. Добавить те же две строки
(`cudnn.deterministic = True`, `cudnn.benchmark = False`) в `seed_everything`
в `main.py`.

### 🟡 4.9 / 4.10 / 4.11 — Число прогонов, разброс, статтесты (сейчас «no»)
Это главная содержательная слабость с точки зрения ревьюера: все числа в
таблицах (точности, число итераций) — судя по всему, **один прогон с seed=0**,
без std / доверительных интервалов / error bars.

Варианты по трудозатратам:
- **Минимум (позволяет честно поставить 4.9 = «yes»):** явно написать в статье,
  что каждый результат — один прогон с фиксированным seed. Это формально
  «указано число прогонов». Но 4.10/4.11 останутся «no».
- **Правильно (флипает 4.9 и 4.10 в «yes»):** перезапустить ключевые
  эксперименты (централизованный CIFAR-10 и федеративный N=10) на **3–5 seed'ах**
  и показать `mean ± std` в таблицах, а на графиках — заштрихованную область
  разброса. Требует GPU-времени, но код уже параметризован через `--seed`, так
  что это просто цикл по seed'ам + агрегация. Наиболее ценно для качества ревью.
- **4.11 (статтесты):** для такого рода статьи Wilcoxon и т.п. обычно не
  обязательны; появится смысл, только если будет ≥5 seed'ов. Низкий приоритет.

**Реалистичная оценка:** 4.9 исправляется мгновенно (декларацией). 4.10 —
средние трудозатраты (перезапуски). 4.11 — опционально.

## Содержательные замечания (не для чеклиста, но ревьюер спросит)

- **Пустые строки «MuonUSign» в таблицах** (`-`/`-%` в Tables 2, 3, cifar_central):
  MuonUSign в экспериментах не запускался/расходился. Стоит либо убрать строку,
  либо явно подписать «diverged / not run», иначе выглядит как пропущенные данные.
- **Разрыв теория↔практика (LMO):** теоремы предполагают точный LMO (полярный
  фактор через SVD), а в обучении используется полиномиальное приближение
  Ньютона–Шульца (5 итераций, коэф. 3.4445/4.7750/2.0315). Это стоит явно
  оговорить как ограничение (частично уже есть в закомментированном Conclusion).
- **Недетерминизм CUDA:** даже с фиксированным seed часть свёрточных/atomic
  операций на GPU недетерминирована. Для полной битовой воспроизводимости —
  `cudnn.deterministic=True` (см. пункт 4.6) + при необходимости
  `torch.use_deterministic_algorithms(True)`. Иначе честнее говорить о
  «статистической», а не «побитовой» воспроизводимости.
- **nanogpt** (`code/nanogpt/`) в статью v2, судя по тексту, не входит
  (эксперименты — синтетика + CIFAR-10). Если он не заявлен в статье, он не
  влияет на чеклист; если планируется включить — добавить в раздел экспериментов.
